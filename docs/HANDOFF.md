# 인수인계 문서 (HANDOFF)

다른 담당자 또는 새 Claude 계정/세션에 이 프로젝트를 넘길 때 읽는 문서입니다.

---

## 1. 프로젝트 배경

K-pop Shorts 채널 **'털어드림'**은 연예인 중심의 시사/논란 **분석형** Shorts를 만듭니다.
단순 가십이 아니라 "이슈가 만든 파장·관계·구조"를 다루는 채널입니다.

문제는 매주 다룰 만한 소재(영상)를 사람이 직접 유튜브에서 찾는 게 비효율적이라는 점.
그래서 **후보 발굴을 자동화**하는 봇을 만들었습니다.

- 1단계 — **주간 메일러(`weekly.py`)**: 유튜브 전체에서 검색어로 후보를 모아 AI가 골라 메일.
- 2단계 — **타 채널 벤치마크(`benchmark.py`)**: "잘하는 채널"을 콕 집어 인기 Shorts를 분석,
  쓸 만한 참고 후보와 기획 인사이트를 추출.

---

## 2. 왜 이 구조로 만들었는가 (핵심 의사결정)

### weekly.py와 benchmark.py를 완전히 분리한 이유
- **주기가 다름**: weekly는 매주, benchmark는 월 1~2회면 충분 (외부 채널 인기 영상은
  주 단위로 급변하지 않음 + Apify·Claude 비용을 매주 4배 쓸 이유가 없음).
- **목적이 다름**: weekly = "이번 주 발송 확정본"(실행 문서), benchmark = "참고용 후보 +
  기획 인사이트"(참고 문서). 둘을 한 리포트에 합치면 둘 다 흐려짐.
- **안전성**: benchmark를 별도 모듈로 두면, 마음에 안 들면 파일만 지워 원복 가능.
  weekly.py(운영 중)를 절대 건드리지 않음.

### benchmark가 history를 "읽기만" 하는 이유
- benchmark의 참고 채널은 weekly가 매주 골라낸 후보 채널에서 자동 추출(빈도순).
- 하지만 benchmark가 history에 **쓰면** weekly의 중복 제거(dedup) 기준이 오염됨.
- 그래서 방향은 **history → benchmark 단방향**. 역방향 코드는 아예 없음.

### 제외 채널 검증을 channel_id 주 기준으로 한 이유
- 채널명은 바뀔 수 있고 동명 채널이 있을 수 있음 → `channel_id`(불변)가 신뢰 가능.
- `channel_name`은 보조 기준으로만 사용.

### weekly.py가 외부 의존성을 최소화한 이유
- GitHub Actions 환경에서 안정적으로 돌도록 표준 라이브러리 위주.
- 유일한 외부 의존성은 `anthropic` SDK.

## 3. 반복적으로 지켜야 하는 규칙

> 전체 규칙은 `CLAUDE.md` 참고. 가장 중요한 것만 추림:

1. `.env`·키·토큰·비밀번호·개인정보를 **출력/커밋/문서화하지 않는다.**
2. **실제 메일 발송 / 실제 배포(push) / 외부 API 과금**은 사용자 확인 없이 실행하지 않는다.
3. `benchmark.py`는 `history/`를 읽기만 한다. 절대 쓰지 않는다.
4. `weekly.py`의 기존 동작은 사용자 확인 없이 바꾸지 않는다.
5. 기존 기능을 바꿀 땐 **영향 범위를 먼저 설명**한다.
6. 모르는 건 추측하지 말고 `확인 필요`로 표시한다.
7. 수정 후엔 **변경 파일·이유·검증 방법**을 요약한다.

## 6. 현재 프로젝트의 리스크

- **운영 중 코드**: `weekly.py`는 매주 자동 실행 중. push하면 즉시 반영 → 검증 없는 변경 위험.
- **API 비용**: Claude(weekly+benchmark), Apify(benchmark)는 과금. 반복 실행 시 비용 누적.
- **YouTube 쿼터**: 일일 10,000 유닛. 로컬 반복 테스트로 소진되면 그날 운영 실패 가능.
- **benchmark 미완성**: 전용 워크플로(`benchmark.yml`) 미작성, `APIFY_TOKEN` 시크릿 등록
  여부 `[확인 필요]`, `benchmark_config.py`가 테스트값 상태.
- **untracked 파일**: `scripts/benchmark.py`, `config/` 가 아직 git에 커밋되지 않음.
- **history 의존성**: weekly의 dedup과 benchmark의 자동 채널 추출이 모두 `history/`에 의존.
  history 파일 구조를 바꾸면 양쪽에 영향.
- **단일 운영자 / 단일 계정 의존**: Gmail·API 키가 특정 계정에 묶임 (`[확인 필요]` — 계정 이관 시 키 재발급 필요).
